# MediaCrawler 专题调研

用 `mediacrawler` 命令行采集多平台内容，补齐视频字幕和图片文字，整理成图文并茂、能直接给人读的文档。完整用法见 `mediacrawler --help` 和各子命令的 `--help`

## 硬规则

- **请求要慢**：命令一条一条顺序跑，不并行，不写循环快速刷。本地节流会自动排队，额度用满就停下等，不要用 `--no-throttle`
- **不绕过验证**：遇到 `SEARCH_VERIFICATION_REQUIRED`、`RATE_COOLDOWN` 或 `AUTH_REQUIRED`，这个平台就停下，换别的平台，或者告诉用户。不要尝试绕过验证、风控或登录
- **不碰隐私**：不写评论者的昵称和个人信息；博主名可以写，因为是公开内容的出处。引用原话每处不超过一句
- **成品给读者看**：制作过程（用了什么命令、哪些没取到、素材统计）只写在过程文件里，不写进成品

## 开始前

```bash
mediacrawler auth status --platform dy      # 三个主力平台 dy、bili、xhs 都查一遍
mediacrawler rate status                    # 各平台 10 分钟额度还剩多少，只读不发请求
mediacrawler transcribe --check             # 视频转文字要 stt；state 不是 ready/installed 时按 missing 提示补模型
mediacrawler ocr --check                    # 图片转文字
```

- **没登录**：`mediacrawler auth login --platform bili --login-mode image`，二维码路径输出在 stderr，文件名带平台（如 `bilibili-login.png`），直接发给用户扫，不要弹系统预览
- **先问清两件事**：读者是谁（第一次去、预算多少、什么时候出发），以及在哪里看（Typora、Notion、飞书、手机）。格式要按看的地方来定

## 额度怎么算

每个平台、每类接口有 10 分钟上限，CLI 和桌面端共用同一份计数。消耗大的是逐条补详情：

| 操作 | B 站 | 小红书 | 抖音 |
| --- | --- | --- | --- |
| `search` 每条作品，默认 | 2 次 | 1 次 | 0 次 |
| `search` 每条作品，`--no-media` | 1 次 | 1 次 | 0 次 |
| 10 分钟内最多补多少条 | 约 40 条 | 约 40 条 | 不受此额度限制 |

`comments` 一次约 2 次，`transcribe --source` 抖音 1 次。B 站批量先用 `--no-media` 粗筛

- `--max-wait` 是愿意排队多少秒，包括等 10 分钟额度恢复，要小于 `--timeout`。默认 3 秒，基本等于不等
- 开始前排不上返回 `RATE_WAIT_EXCEEDED`，开始后排不上返回 `RATE_LIMITED`，都带 `retry_after`。不想等就换平台，晚点再来
- 分页结果 `has_more: false` 才是到底了；`null` 表示这次失败，要看错误码，不能当成没有更多

## 流程

### 1. 采集

每个平台 2～3 个关键词，每个 10 条左右，结果存进专题的 `_raw/`：

```bash
mediacrawler search --platform xhs --query "大理 住宿 怎么选" --limit 10 --non-interactive --max-wait 120 --format json > _raw/xhs-1.json
mediacrawler search --platform bili --query "大理 攻略" --limit 10 --no-media --non-interactive --max-wait 120 --format json > _raw/bili-1.json
```

- 关键词覆盖读者要问的几件事（去不去、住哪、怎么走、吃什么、坑），再加一个带当月的关键词，时效信息往往只有它能搜到
- 优先近期、亲历、有具体价格和时间的内容；商家、导游、只推一家店、文案雷同的标成广告，不当独立证据

### 2. 补文字

```bash
mediacrawler transcribe --source '视频链接' --non-interactive --max-wait 120   # 有平台字幕直接用，没有才转写
mediacrawler ocr --input _raw/xhs-1.json --auto                                 # 只识别正文短、图多的图文帖
mediacrawler comments --source '作品链接' --format json                          # 找反对意见和踩坑，挑几条看
```

- 视频只读字幕，不用理解画面
- 图文帖的干货常写在图里，正文只有一句“见图”，用 `ocr`
- 评论没有发布时间，引用时写“时间不详”

### 3. 补图

- **图文帖**：取前几张图，拼成缩略图总览挑。36 张拼一张大约 1600 token，比一张张看原图省得多
- **长视频**：先读字幕找时间点，比如博主说到某道菜在 01:15，就在 75 秒截一帧：`ffmpeg -ss 75 -i 视频.mp4 -frames:v 1 帧.jpg`。截图里有地图、价目表时可以再跑一次 `ocr --file`
- **短视频**（几分钟内）：`mediacrawler download --source '链接' --quality worst` 下载后内联；长视频只截图
- 只看缩略图总览挑图；手绘线路图、表格这类结构图才看原图，每个专题十张以内
- 配图说明要对上原帖那一张写的是哪里，拿不准就写泛一点

### 4. 成稿

- **按读者的问题拆篇**：一篇总览加几篇专题，比如路线、景点、住宿、美食；每篇自成一体，不靠跳转
- **先交样章**：写完一个章节先给用户看，认可了再铺开，省得整份返工
- **核对**：每个数字回到它引用的原文找一遍；“多人一致”这类说法核一下人数；配图说明核一下地点
- **在目标工具里检查**：在用户实际看的地方打开看一遍，不要用别的预览代替

## 写法要求

- **结论在前**：开头一张横幅图，紧接着“30 秒看完”，再分节展开
- **图文内联**：图片、视频放在对应段落；视频下面列带时间点的要点，比如“`00:13` 开海节 11 月 20 日到 12 月 5 日”
- **来源写在句子旁边**：“（博主名）”加原帖链接；截图和视频片段带时间点，B 站链接加 `?t=秒` 能跳过去，抖音、小红书只能打开开头。不要编号引用、文末素材表，也不要逐行列平台、作者、发布时间
- **每样东西都能回到原版**：短视频下载内联，同时给原链接；长视频截图并链接到对应时间点
- **分歧写双方**：有争议的店、景点，把正反两边都写出来；编者自己的判断标 💡
- **时效信息放最显眼处**：用警告块，比如“11 月 9 日到 30 日索道停运”
- **只留读者需要的提醒**：比如价格以出发前为准、某条是商家说法。“哪些没识别、没取到”这类过程信息不写
- **文件名用中文名词**：总览、路线、景点、住宿、美食，不用 README 这类程序员命名；过程文件收进下划线开头的文件夹
- **适当用 emoji**，表格适合对比和打分，长段落拆成短句

## 不同的输出格式

写法要求只描述意思，落到哪种格式再换写法：

| 意思 | Markdown（Typora、VSCode） | Notion、飞书这类块编辑器 |
| --- | --- | --- |
| 一组图并排加说明 | 表格里放 `<img width>`，三张一行宽 268 | 原生分栏或图片画廊 |
| 结论、警告 | `> [!TIP]`、`> [!WARNING]` | 原生提示块 |
| 原文较长的物料 | `<details>` 折叠 | 原生折叠块 |
| 开头横幅 | 裁成横图放第一张 | 页面封面 |
| 视频 | `<video>` 加本地文件，下面给原链接 | 嵌入原帖链接或上传 |
| 目录 | `[TOC]` | 原生目录块 |

Typora 实测：`==高亮==` 不支持，mermaid 时间线不好看；竖图要限宽，不然一张图占满一屏；链接要按住 Cmd 点。Claude 应用侧边栏的预览不显示 `<img>` 写法的图，以 Typora 为准

## 目录结构

```text
专题名/
├── 总览.md          # 30 秒看完、分篇入口、当月要注意的事
├── 路线.md 等       # 每篇自成一体
├── assets/          # 成品用到的图片、视频、示意图
├── _raw/            # 搜索结果、字幕、OCR、原图、抽帧，不提交，用来重建
└── _build/          # 过程记录、模板和脚本
```

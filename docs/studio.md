# MediaCrawler Studio

简洁的本地桌面采集界面：选择平台 → 登录或自动验证已有会话 → 输入采集目标 → 查看与导出结果

## 本地开发

```sh
npm install
npm --prefix webui install
uv sync
npm run dev
```

`npm run dev` 同时启动 5173 的 Vite 和 Electron，不需要启动 FastAPI 或 8080。只看界面可运行 `npm run dev:web`，浏览器中明确标为预览，真实采集需要桌面 bridge

日常开发保持 Vite 和 Electron 开发窗口运行，前端与 CSS 修改通过热更新生效，不需要每次构建或重启。如果 5173 的 Vite 已启动，只运行 `npm run dev:desktop`。主进程或 preload 改动才需要重启 Electron

仅在检查发布构建时使用以下命令，`npm start` 加载构建文件，不支持 Vite 热更新：

```sh
npm run build
npm start
```

开发模式的 Python 默认使用项目 `.venv`，可通过 `STUDIO_PYTHON` 指定解释器路径。打包模式使用随应用附带的 `Resources/mediacrawler`（独立 CLI 的运行时，桌面用 `-u -m <worker>` 启动内部 worker），不依赖系统 Python。当前启动与打包脚本在 macOS 验证

主题统一由 `next-themes` 管理。桌面 Python worker 连接 Electron CDP 时使用 `no_defaults=True`，保留系统媒体偏好，避免后台连接/断开把主界面临时切成浅色。`desktop/tests/test_cdp_theme.py` 用隔离、无头、静音浏览器回归两类 worker 的反复连接，不访问真实平台

应用图标采用「狐狸与放大镜」：开发模式与 `npm start` 共用主进程加载的 `desktop/assets/icon.png`，macOS Dock 显式设置图标；打包使用 `desktop/assets/icon.icns`

## 桌面与 CLI 构建

| 命令                    | 行为                                             |
| ----------------------- | ------------------------------------------------ |
| `npm run build:cli`     | 只生成 Python 运行时（也就是独立 CLI）           |
| `npm run build:desktop` | 先生成运行时，再生成前端和应用，任一步失败即停止 |

桌面与 CLI 共用一份 Python 运行时 `Resources/mediacrawler`（约 670MB，原来桌面和 CLI 各带一份），完整目录不可只保留一个可执行文件。OCR 和语音转写都可拆：构建环境没有 rapidocr 就不带 OCR，没有 `vendor/stt` 就不带 stt，界面隐藏对应入口并在设置里说明

语音转写的 `stt` 由 ai-voice 单独构建成 zip 包（自带解释器，只支持 macOS arm64），把它解压出的 `stt` 文件夹直接复制到仓库根目录的 `vendor/stt`（不进 Git，没有就当没有这个功能）；打包时检查 `manifest.json` 的平台和接口版本，对得上就附带为 `Resources/stt`，没有就不带。资源目录在打包后原样再复制一遍，保留相对符号链接（打包器自带的复制会把它们改成指向构建目录的绝对路径）

产物在 `dist/desktop`，目前生成本机平台/架构的应用目录；macOS 签名、公证与 DMG 尚未配置。macOS 设置提供「安装命令 / 移除命令」，只在附带 CLI 的发布版可用，开发模式显示为禁用，未包含 CLI 的发布版隐藏；其他系统暂不提供此入口。通过 `/usr/local/bin/mediacrawler` 软链接指向当前应用内 CLI，不修改 shell 配置。目录不可写时通知失败，不自动提权；同名文件或其他来源的链接不覆盖、不删除。移除只删当前应用的链接，不动 CLI 本体、登录数据或应用。移动应用后旧链接需要先移除，避免覆盖其他安装来源

本次已实际生成不附带 CLI 的 macOS arm64 应用，并验证包内两个 Python worker 能加载依赖、启动 Playwright driver 和访问受控本地 CDP 测试端点；未重做真实账号登录/采集，严格模式的顺序与缺失产物行为通过单元测试

## 工程检查

Node 使用 `.nvmrc` 指定的 22，保留 npm 与两份 package-lock.json。初次安装：根目录 `npm ci`、`npm --prefix webui ci`、`uv sync --locked`。Prettier/ESLint 安装在根目录，WebUI 脚本共用根配置，因此单独安装 WebUI 不包含完整检查工具

```sh
npm run format        # 格式化桌面 JS、WebUI、配置和本文档
npm run format:check  # 只检查格式
npm run lint          # JavaScript、TypeScript、React Hooks
npm run lint:fix      # 可自动修复的问题
npm run typecheck     # 只检查类型，不生成构建文件
npm run check         # 格式 + Lint + 类型
npm run check:all     # 上述检查 + 桌面 Node/Python 测试
```

参考 tobe-lab 的 Prettier、ESLint flat config 和 Tailwind 类名排序，按本项目适配 Tailwind 3、React 18、TypeScript 5.6；保留两空格、单引号、无分号和现有 80 列布局。Prettier 负责格式，ESLint 负责代码问题，eslint-config-prettier 消除重叠规则；EditorConfig 统一编码和换行，Python 使用四空格

检查范围覆盖 `desktop` 中 JS、`webui` 源码及工程配置；不格式化 Python、上游文档/签名库、生成资源、锁文件和 `.temp`。Python 继续通过现有 pytest 检查。已有 pre-commit 配置保留，不自动安装 Git hooks

`.github/workflows/studio-checks.yml` 在 PR、main/codex 分支推送或手动触发时运行同一套检查，使用锁文件安装依赖；不发起真实采集、打开浏览器或生成发布包。日常开发仍保持 Vite 热更新，不要求先构建

## 错误日志

设置底部「打开日志目录」打开当前应用数据目录的 `logs`；macOS 默认 `~/Library/Application Support/mediacrawler-studio/logs/`，`STUDIO_USER_DATA` 覆盖时随之迁移。当前文件 `studio.log`，按大小轮转为 `studio.1.log` 至 `studio.4.log`，单文件最多 5 MiB，共保留 5 个，约 25 MiB；跨重启继续追加，超过上限删除最旧文件

日志采用逐行 JSON，记录时间、级别、来源、事件与诊断信息。覆盖启动/主进程未捕获异常、IPC 失败、磁盘保存失败、采集/下载/播放解析失败，以及主界面控制台警告/错误、preload 错误、加载失败与渲染进程退出。监听在页面加载前安装，不依赖 React 成功渲染；不监听第三方登录页面与播放器 iframe

统一入口 `desktop/logging/logger.mjs` 调用 `redact.mjs`：过滤 Cookie、认证头、密码、Token、会话与签名字段，移除 URL 凭据/查询参数/片段，替换邮箱、手机号和用户主目录。业务入口不传整个请求、搜索正文、账号资料或平台响应；Python 通过 `diagnostics.py` 白名单发送异常类型、文件名、行号和函数，不发送异常原文、源代码行或局部变量，上游原始 stderr 继续丢弃。日志字段过滤不是任意文本均可安全存储的承诺，新增入口仍应只传诊断所需字段

单条记录上限 32 KiB，过大时保留事件与截断标记；每分钟最多 120 条，下一分钟收到日志时汇总被抑制数量。目录/文件分别使用 0700/0600 权限，写入失败不打断业务，只向终端提示一次。只有桌面版落盘，独立 Vite 预览仍使用浏览器控制台；主进程/preload 更新需重启 Electron 才启用

本次验证：轮转上限、跨重启、超长记录、限流、磁盘失败、脱敏、循环对象与第三方 iframe 排除均通过；隔离临时 userData 的隐藏 Electron 实测控制台错误、未捕获异常与 Promise 拒绝能落盘并脱敏。未重启正在使用的开发窗口，未构建安装包

## 视频播放

B 站、抖音和小红书的视频详情可以直接播放，其他平台详情只展示图片。设置里的开关都是否定含义、默认不勾选：「禁止自动播放视频」不勾选时打开详情直接播放，「自动播放时静音」不勾选时有声。抖音和小红书直接用详情带回的地址，不额外请求平台，地址失效时才刷新一次；两者的 CDN 校验来源页，主进程只给媒体请求改写 Referer。开发环境下，脚本读取 `window.__STUDIO_DEBUG__` 后一分钟内打开的视频都静音，不改动设置

## 图片与视频下载

详情底部的「下载」菜单可下载整组图片或视频，默认直接保存到系统 Downloads，不建子文件夹，文件名为“作者 - 标题”，同名自动加序号；设置中「下载前询问」默认关闭，开启后每次选择目录，开关会记住。下载可取消，关闭详情后右下角仍可取消；失败弹窗区分资源过期、平台限制、尚不支持、需要登录、网络和磁盘问题。下载不会覆盖已有采集结果或历史记录

复用仓库 `media_downloader` 的流式传输、重试、备用地址与 ffmpeg 合流。图片按当前记录顺序保存；视频优先复用已有媒体候选，缺少 FFmpeg 或地址失效时，通过已有会话尝试单文件兜底/刷新一次：B站、抖音、小红书、微博、快手复用原生提取器；知乎/贴吧尝试平台响应或页面明确提供的直链。B站优先音视频合流，无 ffmpeg 时尝试完整 MP4；共享下载层已支持非加密点播 HLS（需要系统 FFmpeg），包括主清单选择、独立音轨、初始化片段及字节范围；直播、加密/DRM HLS、普通多段视频及没有可用直链的内容仍不支持，不将部分片段当作完整视频

下载任务与采集/登录清理互斥；主进程只接受已有结果 ID，使用系统 Downloads 或原生选择的目录，页面不能传入任意下载地址或落盘路径。媒体请求不携带登录 Cookie，重定向逐跳检查 HTTPS 公网地址。临时文件放在目标目录内部，正常取消清理半成品，已完成文件保留；强制终止进程可能留下隐藏临时目录

验证使用模拟响应和本地测试服务器，覆盖图片顺序、部分失败保留、404/410/403/401、错误页面/流媒体清单拒绝、取消清理、地址刷新与互斥。后续已用共享 CLI 下载链路实存 B站、抖音、小红书代表素材；不等同七平台桌面下载全部线上验收。HLS 通过本地生成素材验证；Python 已随桌面应用分发，ffmpeg 暂不捆绑

## 博主采集

博主信息显示在输入框里，点叉号回到推荐流，右侧可以在已采的作品里按标题和正文搜索，只筛本地结果，不发平台请求。

视频详情右栏分正文、字幕、评论 Tab，“提取字幕”在字幕 Tab 里，依赖 `stt` 语音转写服务，安装版自带，没有再用本机的 `stt` 命令：打开应用时检查一次，找不到 `stt` 就隐藏入口；缺模型时字幕 Tab 和设置里列出缺什么、多大、放到哪个目录，带下载页、打开目录和复制下载命令，不替用户下载，放好后点“重新检查”；设置里还显示来源和版本（内置 stt 0.1.0 或本机 stt）；后台空闲退出时提取会自动叫醒。提取中按视频时长显示预计剩余时间，并用最近 5 次实际耗时校准，超出预计后改为安抚提示。有平台字幕时直接显示；生成的字幕按作品 ID 存在应用缓存 `app-cache/transcripts/`（一条一个文件），最多 100 条，超出淘汰最早的，可以重新生成。有字幕后下载菜单多“下载字幕”，可存 SRT 或 TXT，保存位置跟随“下载前询问”。

B站、抖音、小红书 Tab 的输入框旁有“找博主”，搜索后点击博主立即开始采集；弹窗里的“最近采集”直接打开已有记录，不发起搜索。设置的“体检”页只有一个按钮，全程显示文字进度：没登录的平台只查网络和扫码入口，登录的 B站、抖音、小红书、知乎再把推荐、博主页、详情、下载、搜索各走一次，看条数和字段是否变化。下载只请求媒体地址的前 2 字节验证可用，不真正下载；只在手动点击时运行，同样走平台节流，遇到风控立即停止该平台。B站、小红书的搜索和博主页，以及知乎搜索，都先用列表字段出卡片（一页一次请求），打开时再取详情并合并进同一条记录；列表没给封面的卡片进入视口后在后台补取，你打开的详情优先。勾选采集评论时仍逐条取完整内容，命令行也始终取完整内容。推荐流右上角可以刷新：新内容回来才替换列表，优先用后台备好的一页；缓存有效期 30 分钟，临近过期时只在你正在使用当前平台时后台补一份，窗口闲置不发请求。平台排队超过 12 秒或处于冷却时，请求会返回需要等待的时间：滚动加载显示“继续加载”，倒计时结束后再滚动或调整窗口会继续（最多 3 次），详情显示重试按钮，后台请求静默重试几次后放弃。卡片和详情里的作者名可以点：B站、抖音、小红书、知乎直接进博主主页（知乎依次是回答、文章、视频，也可以粘贴 `zhihu.com/people/...` 链接；知乎关键词搜索仍是固定条数，不能滚动续采；知乎 Tab 默认显示推荐流，卡片自带正文，打开详情不再请求，详情按文章单栏排版，图片在原文位置），看过的博主打开已有记录不再请求，输入框左侧的返回键回到刚才的列表和位置；拿不到主页地址时（旧记录、链接采集），B站、抖音打开“找博主”并搜索这个名字，其他平台按关键词搜索。平台忙或未登录时只显示名字。也可以直接粘贴主页链接（`space.bilibili.com/UID`、`douyin.com/user/...`、带 `xsec_token` 的小红书主页）或分享短链（`b23.tv`、`v.douyin.com`、`xhslink.com`），自动进入博主模式，数量上限 200。小红书可以粘贴博主主页链接或 App 分享文案（需带 `xsec_token`，暂不支持按名称找博主）。抖音和小红书的数量默认“自动”，选具体数字则按数字采。结果滚到底会自动继续采集，并入同一条记录；内容不足一屏、任务被停止或失败时不自动继续，可手动点“继续采集”。粘贴 App 的整段分享文案也可以，会提取其中的平台链接；`v.douyin.com` 主页短链会自动换成完整主页链接。采满一批且博主还有作品时，结果末尾可继续采集，新内容并入同一条记录。搜索与采集共用平台页面，同平台互斥，每次操作只发一个搜索请求。搜索频率限制与 CLI 共享，见 [CLI 访问节奏](cli.md#访问节奏)

开发环境可用 `window.__STUDIO_DEBUG__` 读状态、驱动操作（`snapshot()`、`detail()`、`results()`、`actions.openLink()`、`frame.*`、`imageText.*` 等），生产包不含该模块。`npm run probe -- <命令>` 连上正在运行的开发版，只通过这个入口验收，结果输出 JSON：`snapshot`、`open`、`image-text`、`frame`、`transcript`、`comments`、`shot`、`eval`，见 `scripts/studio_probe.py`

## 推荐流

B站、抖音、小红书在没有采集结果时显示平台首页推荐（接口 `get_home_feed`，节流分组和上限见 `docs/cli.md`）。打开时先多备一屏，之后只有用户真实滚动才翻页，一次运行内切 Tab 复用缓存不重新请求。推荐不写历史；开始采集后被结果替换，清空输入框回到推荐。

过期：列表超过 30 分钟时，切回该平台或窗口重新聚焦先显示旧内容，新内容和前 10 张封面就绪后无动画替换；等待期间用户滚动、点击、打开详情或搜索就放弃替换，旧内容留着。

预取：主进程给已登录平台各备一份首屏（`desktop/feed-scheduler.mjs`），存到用户数据目录的 `app-cache/feed.json`，30 分钟内有效，切到该平台或重新打开时直接用，用掉后等平台静默 60 秒再补一份，所以每次打开都是新内容。后台请求一次一个、当前 Tab 优先，缓存过期不会自动重拉。

竞态：推荐请求只读且不跳转页面，不占平台互斥，采集、下载不会被“请先结束当前任务”拦住。用户发起的请求优先：同平台开始采集、搜博主、下载或翻页时后台预取立即让路，结束后再补；打开时预取还在进行就接上同一个请求；后台请求要排队超过 3 秒就放弃，不占节流名额。被取消的结果不进缓存，账号失效或退出时清掉缓存。卡片只有摘要，打开详情走单条链接流程补正文、图片和媒体

## 列表与详情的数据分层

采集时只保存稳定内容（ID、标题、正文、封面、作者、数据）。B站的播放地址、清晰度、字幕和章节每条要多发两次请求且地址会过期，批量采集时不取；抖音和小红书在列表阶段已有详情，直接复用，不多发请求。详情用已有数据立即打开，缺少媒体信息时后台补全并写回记录，下载菜单里“自动”立即可用，清晰度显示加载中。补全不占平台互斥，采集和下载不受影响；未登录时不补全。下载时若记录里的地址失效或缺失：自动画质走平台重新解析，指定清晰度重新取一份后再选档位

筛选使用平台原生搜索请求，不对已经采集的结果做本地过滤。白名单在 `desktop/search-options.json`，渲染层、主进程及 Python 共用；B站相对时间在开始搜索时转换为固定时间窗口。贴吧的帖子类型参数在当前原生客户端没有实际进入请求，因此不展示。无筛选时保留原有默认行为；前后端拒绝跨平台和未知值。参数传递已通过离线测试，不代表所有平台当前线上筛选均已实测

下载菜单按已有媒体候选的真实尺寸合并画质：多档展示“自动（推荐）”及具体档位；只有一档或缺少尺寸时直接默认下载。竖屏以短边标记；指定画质不悄悄降级，缺档、链接失效、缺音轨或 FFmpeg 时返回对应失败提示。“自动”保留原有刷新和单文件兜底策略。视频的单张封面标为“下载封面”，明确无视频的图文隐藏视频入口；旧记录没有媒体信息时保留默认下载，不伪造画质。未新增音频转写、转码配置或下载中心

## 界面与行为

- 七个平台：B站、抖音、小红书、知乎、微博、贴吧、快手；各自保留输入、数量和结果。不同平台可以同时采集。切换 Tab 后原任务继续，停止按钮只作用于当前平台。采集、下载和退出登录共用该平台的页面，同一平台一次执行一项操作
- 品牌图标复用 `tobe-lab` 的 `BrandIconBase`，使用同版 `simple-icons@16.21.0`，用于平台 Tab、结果标签和详情；抖音使用 `siTiktok` 音符标志。SVG 跟随文字颜色，常规操作继续使用 Lucide
- macOS 使用原生融合标题栏：红绿灯、产品标题和主题控件共用一行，背景跟随主题；顶部固定，空白区域可拖动，主题控件独立接收点击。网页预览不模拟红绿灯，其他系统保留原生窗框
- 一个输入框接受关键词或作品链接，粘贴链接自动识别平台；搜索默认 5 条；数量弹层提供 5/10/20/50/100 快捷选项及自定义整数输入（1–100），确认后保存，关闭则丢弃未确认输入。组件使用现有 shadcn Popover/Button/Input，未新增依赖。输入框旁的采集选项使用紧凑 Dialog，按平台展示原生筛选及评论设置；修改点“应用”后用于下一次采集，关闭丢弃未应用更改，“重置”只改弹窗草稿。评论默认关闭，每篇最多 20 条主评论、另取 20 条回复；筛选按平台保存并随历史任务恢复，作品链接模式不应用搜索筛选
- 默认在内容区域展示内联二维码，复用隐藏、静音的独立平台分区；加载时显示假码和半透明遮罩，失败时在原位置刷新，不自动弹出完整平台窗口。旧的完整页面模式保留底层能力，不作为默认入口
- 取码实际超时为 30 秒，与预估独立。预估初始 8 秒，按各平台成功取码耗时更新平均值，显示范围 3–20 秒；预估结束显示“即将完成，请稍候”。只保存每个平台的计数与均值，100 次之后按 1/100 权重更新；不记录扫码等待、失败或二维码内容
- 二维码拿到后停止取码超时，继续等待用户扫码；当前可见平台每 2 秒轻量读图，后台每 60 秒检查，切回时补同步。日常轮询不点击登录、不重载页面；同图不重复推送，短暂读不到图保留现有码。只有可见登录区域明确提示过期才复核后刷新；刷新失败停止自动重试。识别到扫码成功或手机确认后停止换码，展示“请在手机上确认”，继续等待账号结果；确认状态优先于过期提示。二维码下方常驻刷新按钮：等待进程不动，只重载隐藏的平台页换新码，旧码盖遮罩留在原地，新码就绪后替换；换码失败自动走一次完整流程（重启等待进程并重载），用户无需选择。手动完整流程在刷新按钮的右键菜单「重新连接」，或按住 Option（Windows 为 Alt）点击，悬停提示会说明；其余只在到期自动换码、失败兜底和出错后的原位重试中出现。窗口重新获得焦点或切回该平台时，已到期的码自动更换，并重新计算自动换码次数。扫码等待窗口 5 分钟（任务上限 330 秒），到期不计入取码失败次数：用户正看着该平台时自动换码，连续无人操作换 2 次后停下并提示刷新；在后台到期不发请求，切回该平台时才换码；手机确认中到期不换码，避免打断登录。平台 DOM 信号有覆盖边界，不把无法识别当作确认过期；切换平台复用已有任务，迟到结果不覆盖新任务
- 弹层与独立窗口复用同一平台页面和 CDP target；弹层尺寸随主窗口调整，主界面重载时先撤下原生层再恢复。平台内容无产品 preload、默认静音，按需创建并在后台保留；平台网页本身仍由各站点控制
- 已登录账号旁提供退出图标和「退出登录」悬停提示，先尝试平台登出并核验，再清理当前平台的本地登录会话；平台退出无法确认时明确提示，保留其它平台和采集记录；任务运行时禁用，退出后由用户主动重新登录。设置中的清除全部登录态仍保留
- 账号入口位于平台栏右侧，显示可获取的头像与昵称；资料缺失或头像加载失败时使用默认头像。未登录禁用采集条件，不再使用遮罩或居中登录长条
- 启动分三级并行准备登录：B站立即开始，抖音/小红书延迟 1.5 秒，其余平台延迟 4 秒，延迟从应用启动计算而非等待上一组完成。选中尚未启动的平台立即取消其排队延迟；已启动任务继续运行，切换平台或打开历史不取消连接。已有会话自动验证，无有效登录时在内容区展示缓存二维码；取消或失败后只保留重试入口。同平台重复请求合并，单个平台停止/退出不影响其他平台；采集接管同平台页面前先停止其登录任务
- 已登录后采集仍会检查实际会话；失效时重新锁定条件，扫码完成后继续原采集，保留已填关键词/链接
- 页面显示实际阶段、已获得条数和耗时，允许取消；验证码由用户在真实平台页面完成
- 采集按钮不带装饰箭头，忙碌时原位显示 loading 和停止；数量、完成状态、耗时以 text-xs 放在窗口右下角，错误/警告可展开详情；标题栏、结果区和详情内部不使用横向分割线

## 结构

```text
React 界面 → preload bridge / IPC → Electron 主进程
                                       ├─ Python 子进程（NDJSON 标准输入输出）
                                       └─ 独立 session 的平台窗口
Python → 页面级 CDP → 平台 Cookie / localStorage → 原生采集客户端
```

- `desktop/main.mjs`：窗口、IPC、导出和退出管理
- `desktop/service.mjs`：任务进程、分平台结果、取消和恢复
- `desktop/library.mjs`：历史批次、页面输入、原子保存与旧结果迁移
- `desktop/platform-windows.mjs`：按平台持久化会话，默认静音，无产品 preload
- `desktop/worker.py` / `crawler.py`：桌面协议与原生采集编排
- `desktop/content/`：桌面与 CLI 共用的 schema v3 媒体候选、字幕及平台能力补齐；字段与状态见 [CLI 说明](cli.md)
- `desktop/native_platforms.py`：七个平台的原生引擎注册
- `desktop/extra_platforms.py`：知乎、微博、贴吧、快手的搜索与作品采集
- `desktop/comments.py` / `extra_comments.py`：评论与回复的有界分页，复用平台 client 及脱敏存储转换
- `desktop/page_context.py`：按目标页面读 Cookie，避免 Playwright 默认 context 混淆 Electron 分区
- `webui/src/studio/`：采集表单、结果、详情、主题和状态

HTTP 后端已从桌面通信链路移除；CDP 会在本机随机端口监听，用于 Python 访问 Electron Chromium。产品 UI 按精确窗口来源检查 IPC，平台页面不开启 Node.js

macOS 默认数据位于 `~/Library/Application Support/mediacrawler-studio/`；平台 Cookie/localStorage 保存在独立 Chromium partition，每批结果位于 `history/<id>.json`，页面输入与当前查看的批次保存在 `workspace.json`。旧 `results.json` 首次迁移后保留，不覆盖原始文件。不导入旧工程 Cookie，不把凭据传入 React，也不记录上游原始响应日志

## 页面与历史存储

- 历史保存平台、关键词或链接、数量、时间、状态和结果快照；仅登录验证不创建记录
- 输入、数量、各平台选中的历史批次在重启后恢复；结果区不再提供二次筛选搜索
- 主进程统一写入 JSON 文件，临时文件写完后 rename，IPC 不接受任意文件路径；导出按当前平台与批次校验，不使用全局最后一批结果
- 启动时读取历史文件建立索引；当前面向少量内容批次，历史数量很大时可再迁移 SQLite。暂未加入删除或自动清理，不默默丢弃历史
- IndexedDB 是浏览器按 origin 管理的本地数据库；Electron 的默认 session 数据通常也位于 userData/sessionData。这里使用主进程文件存储，避免 localhost 开发预览与 file: 桌面版各存一套。无须启动 HTTP 后端
- 图片仍为平台远程地址，可能过期；保存文字与链接快照不等同媒体离线归档

依据：[Electron app 路径](https://www.electronjs.org/docs/latest/api/app#appgetpathname)、[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

主窗口滚动：标题栏固定，页面主体使用默认 shadcn ScrollArea 独立滚动；滚动条不经过顶部红绿灯区域，底部留 12px 标准间距避开窗口圆角。沿用组件默认 hover 显隐与覆盖式滚动条，保留滚轮、键盘及拖动操作

多语言与会话清理参考：[react-i18next](https://react.i18next.com/latest/usetranslation-hook)、[Electron Session](https://www.electronjs.org/docs/latest/api/session#sesclearstoragedataoptions)

### 通知覆盖

采集完成、空结果、失败、停止保留结果，以及扫码成功、恢复默认设置均有一次性反馈。自动检查已有会话、关闭登录弹层、普通设置切换、二维码轮询、历史恢复不弹成功通知。主进程拒绝启动与连接失败会通知；语言/主题持久化失败明确提示，恢复默认设置仅在全部保存成功时提示成功

任务通知按任务身份与状态变化去重，重复 IPC、初始快照不会重放。评论不全或记录落盘失败用 warning；结束后迟到的保存失败更新同一条通知。下载部分成功只在失败弹窗注明已保存数量，不再叠加成功通知；取消且已有文件时说明保留数量。复制、导出、退出、清理登录态、CLI 安装移除等已有反馈保留；图片/视频/二维码已有就地错误不重复 toast

### 设置中的连接检查

设置 → 连接检查 → 检查全部平台，复用 CLI 的网络诊断及七平台实际取码检查；仅手动启动，不要求扫码。使用独立内存分区的隐藏静音页面，最多同时检查三个平台，不修改正在使用的二维码和登录态。重复请求合并，关闭设置后继续执行；全程最多140秒，完成或退出时释放页面与检查缓存

完成只通知一次：成功显示“全部平台正常”；异常按原因合并平台，例如“抖音、小红书：连接超时；贴吧：需要验证”。断网统一提示“网络未连接”，未完成项不算成功。网络探针/测速仅作诊断参考，平台状态以真实浏览器取码结果为准，不因单个测速节点失败误报平台失效。详细报告写入轮转日志，不在设置中堆叠诊断数据

检查中展示网络阶段和「已检查 X/7」；若检查进程无法连接浏览器，统一提示「检查连接超时，请重试」，不把未检查的平台误报为全部故障。主动打开本地历史无需登录，点击扫码会回到当前平台已有二维码；采集过程中等待扫码的取消操作会停止该采集任务
